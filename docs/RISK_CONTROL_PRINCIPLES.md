## 一、核心原则（一句话总览）

> **风控与入场解耦；长持仓用趋势破位风控；风控效果不用胜率衡量。**

---

## 二、4 条强制原则

### 原则 1：风控与入场解耦

**定义**：
- 入场逻辑（因子）：决定**什么时候买、买什么**
- 出场逻辑（风控）：决定**什么时候必须卖**
- **两者独立可替换**——可以换因子但保留风控，反之亦然

**反例（禁止）**：
```python
# ❌ 错误：风控和入场耦合
if rsi < 30 and pnl > -0.05:  # RSI 入场 + 5% 止损混在一起
    sell()
```

**正例（推荐）**：
```python
# ✅ 正确：入场和风控分开判断
if trigger_entry_signal(...):  # 纯入场因子
    buy()
if trigger_risk_exit(...):      # 纯风控触发
    sell()
```

**价值**：
- 风控组件可跨策略复用（如 close<MA60 暴跌保护）
- 因子迭代不会破坏风控稳定性
- 风控规则便于独立审计和回测

---

### 原则 2：长持仓用趋势破位风控（暴跌保护）

**定义**：
- 持仓周期 ≥ 1 个月 → 用**暴跌保护**（趋势破位）
- 持仓周期 < 1 个月 → 用**移动止损**（利润回吐）
- **不要混用**

**暴跌保护机制（C11/C18 验证）**：

| 项 | 规则 |
|---|------|
| 触发条件 | `close < MA60`（收盘跌破 60 日均线）|
| 触发动作 | 立即平仓全部持仓 |
| 恢复条件 | `close > MA60` 且入场因子重新确认 |
| 衡量指标 | **最大回撤 / 救回金额 / alpha 增量**（非胜率）|

**实测验证（C18 长数据 11 ETF）**：

| 场景 | buy & hold | C11（含暴跌保护）| 救回 |
|------|:----------:|:-----------------:|:----:|
| 512690 酒 | **-41.48%** | **-0.29%** | **+41.19pp** |
| 512980 传媒 | -3.41% | +61.09% | +64.50pp |
| 159857 医药 | -0.54% | +59.38% | +59.92pp |

**结论**：暴跌保护在长持仓策略上**真实救回 40%+ 暴跌**。

---

### 原则 3：风控效果不依赖胜率衡量

**核心区分**：

| 维度 | 入场逻辑（因子）| 出场逻辑（风控）|
|------|----------------|-----------------|
| 衡量指标 | 胜率 / IC / 准确率 | **最大回撤 / 救回金额 / alpha 增量** |
| 改进方向 | 提高预测力 | **降低尾部风险** |
| 评估周期 | 月/季度 | **5 年一次完整牛熊** |
| 失效信号 | 胜率 < 50% 持续 6 月 | **回撤 > 历史最大** 或 **暴跌未救回** |

**反例（禁止）**：
```
"风控规则 A 胜率 37%，无效，应删除"  ← 错误：风控不该用胜率衡量
```

**正例（推荐）**：
```
"风控规则 A 在 11 长数据 ETF 上救回 3 次暴跌（-41%/-3%/-0.5%），
 单笔最大回撤从 -41% 降至 -0.3%，alpha 增量 +41pp，应保留"
```

### 原则 4：风控组件化 + 配置化

**强制要求**：
- [ ] 风控规则**写进配置**（不内联在代码里）
- [ ] 风控组件**独立模块**（不与入场逻辑混在一个类）
- [ ] 风控触发时**有日志**（含触发时间、当时盈亏、市场状态）
- [ ] 风控参数**可网格测试**（用于找最优阈值）

**当前风控配置位置**：
```
src/risk/config_types.py    # RiskConfig dataclass
src/risk/manager.py        # RiskManager.check_entry/exit
```

## 三、风控原则 Checklist（策略设计时强制走）

### Step 1：定义持仓周期

- [ ] 策略持仓周期是？短（< 1 月）/ 中（1-3 月）/ 长（> 3 月）？
- [ ] 入场因子的预测周期是？（应与持仓周期匹配）

### Step 2：选择风控机制

| 持仓周期 | 风控机制 | 触发条件 |
|---------|---------|---------|
| 短持仓（< 1 月）| **移动止损** | 最高价回撤 5% |
| 中持仓（1-3 月）| **混合**（移动止损 + MA60 兜底）| 双重触发 |
| 长持仓（> 3 月）| **暴跌保护**（趋势破位）| `close < MA60` |

### Step 3：风控组件化

- [ ] 风控规则独立于入场因子？
- [ ] 风控参数在配置文件中？
- [ ] 风控触发有日志？

### Step 4：风控效果评估（按原则 3）

- [ ] 报告**最大回撤**（不是胜率）？
- [ ] 报告**救回金额**（暴跌 ETF 上 buy & hold vs 策略）？
- [ ] 报告**alpha 增量**（策略 alpha - 无风控 alpha）？
- [ ] **不用胜率衡量风控**？

### Step 5：风控的边界检查

- [ ] 风控规则之间**不冲突**？（如不能同时"跌破止损"+"移动止损"）
- [ ] 风控触发后**恢复规则**清晰？
- [ ] 风控在**震荡市**不会频繁假触发？（MA60 比 MA20 更稳）

## 四、当前风控体系对账

### 4.1 现有风控（src/risk/manager.py）

```python
@dataclass
class RiskConfig:
    stop_loss: float = -0.06      # 固定止损 -6%
    stop_profit: float = 0.10    # 固定止盈 +10%
    max_position: int = 1       # 最大持仓数
    max_loss: float = -0.15     # 最大总亏损 -15%
    hold_days: int = 5          # 最大持仓天数
```
