## 关键教训（写进 MEMORY.md）

### 1. "测试通过"≠"系统健康"
- 4 个 collection error 阻断测试但没人发现
- "全过"是假的——是"还没跑到失败的"
- 教训：必须 `pytest --co -q` 健全性检查 + pre-flight check

### 2. is_real 字段是金矿
- trade_history.emotion / is_real 是"用户实盘 vs 程序测试"分水岭
- 不看 is_real 会把测试数据算成实盘资金
- 教训：所有聚合查询默认 `WHERE is_real=1`

### 3. 派生表/缓存是债务
- `positions` 表是历史设计，US-015 标记"已废弃"但没删
- 任何 `SELECT FROM positions` 都会看到脏数据
- 教训：软删除要有"清空+schema 保留"明确时间表

### 4. "fix 数字" vs "更新测试意图"
- US-015 测试期望 2 只持仓，但生产数据有 510300 残留
- 应该修实现（过滤 reference 池）而不是改测试期望
- 教训：测试失败时先看数据真实性，再决定改哪边

### 5. 命名准确性
- daily 模式日志"总资产: 9,170 元"——实际是现金，不是总资产
- 应该是"现金"（持仓 0 时代替总资产，有持仓时让用户自己加）
- 教训：日志字段名要反映实际含义
