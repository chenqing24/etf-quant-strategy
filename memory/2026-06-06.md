## 21:30 阶段：Step 5 验证遇到 3 个数据源问题（🚨 诚实标记）

### 🚨 重大发现：3 个数据源都失败/受限

实测 512660 段 3 (2023-2026) 用 `DataSourceRouter.fetch_daily_range`：

| 数据源 | 实际结果 | 原因 |
|--------|---------|------|
| **AKTools** | ❌ HTTP 500 | 服务持续报错 Internal Server Error |
| **Tencent**（router 版）| ❌ 无数据 | router 的 _fetch_tencent 与 TencentETFetcher 实现不同 |
| **BaoStock** | ⚠️ 限 100 条 | baostock API 自身限制（query_history_k_data_plus 默认 100）|
| **Tushare** | ❌ 无备援 | 路由未实现完整回退 |

### 🔍 对比：TencentETFetcher 直拉

| 工具 | 结果 |
|------|------|
| `DataSourceRouter.fetch_daily_range` | 100 条（baostock 降级）|
| **`TencentETFetcher.fetch_etf(days=1825)`** | **1825 条 ✅** (2018-11-23 → 2026-06-05, 7.5 年) |

**结论**：`DataSourceRouter` 现状**不能**满足"5 年"目标。`TencentETFetcher` 直拉可满足。

### 5 个诚实标记（按规则 22）

1. **AKTools 服务挂了**（HTTP 500）— 不是代码问题，是 Docker 服务问题
2. **DataSourceRouter._fetch_tencent 与 TencentETFetcher 实现不同** — router 版可能没正确处理单段 5 年
3. **BaoStock 限 100 条** — 自身 API 限制，无法绕过
4. **设计方案 vs 实际能力有 gap** — 设计假设多源能拉 5 年，实际只能拉 5 个月（baostock）
5. **本任务可补救** — `TencentETFetcher` 直拉可拉 7.5 年（满足"5 年"目标）
