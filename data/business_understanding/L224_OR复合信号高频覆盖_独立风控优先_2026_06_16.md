# L224（etf_strategy 子项目）：OR 复合信号中暴跌保护被高频信号覆盖（2026-06-16）

## 场景

用户："B 和 C"（基于 L223 暴跌保护原则 + 风控原则文档化）

按 L223 + C19 实验：
- 测试 5 个暴跌保护阈值（MA20/MA60/MA120/ATR2x/DD-20%）
- **5 个阈值结果完全一致**（收益/胜率/alpha/最大回撤全部相同）

debug 发现：C11 的 sell_signal 是 OR 复合：
```python
sell_signal = sell_ma5 | sell_rsi | sell_obv | crash
               ↑ 高频触发    ↑ 中频      ↑ 中频      ↑ 低频
```

sell_ma5（close<MA5）在震荡市**几乎每天触发**，掩盖了暴跌保护（crash）的触发机会。
5 个阈值没差异 = 暴跌保护**实际上没起作用** = **L223 原则在 C11 当前实现下形同虚设**。

## 关键发现（按规则 6.1 诚实标注）

### 🔴 发现 1：OR 复合信号中，高频信号会覆盖低频信号

**验证数据**（ETF 512690，644 天）：
| 信号源 | 触发次数 / 644 天 |
|--------|:----------------:|
| sell_ma5（close<MA5）| 大量（每个下跌日都触发）|
| sell_rsi（RSI>70）| 中等 |
| sell_obv（OBV<MAOBV）| 中等 |
| crash（close<MA60）| 381（59%）|

**当 OR 复合时**：
- sell_ma5 已经覆盖了大部分卖出机会
- crash 即使差异巨大（MA20=409 vs MA120=364），也**被 sell_ma5 抢占**
- 结果：crash 触发与否**不影响最终持仓**

### 🔴 发现 2：当前 C11 暴跌保护 = sell_ma5 的冗余备份

**含义**：
- C11 报告 +68.97% / alpha +23% 实际来自 **sell_ma5（趋势破位）+ 长期持有**
- **close<MA60 没真正起作用** = 阈值换成什么都一样
- L223 原则仍成立，但**当前实现让暴跌保护"形同虚设"**

### 🟢 发现 3：独立风控逻辑才能测出阈值差异

按 L224 教训（**独立风控优于 OR 复合**）：

```python
# ❌ 错误：OR 复合（高频覆盖低频）
sell_signal = sell_ma5 | sell_rsi | sell_obv | crash

# ✅ 正确：独立风控逻辑
def should_sell(df):
    # 优先级 1：暴跌保护（最高优先级，强制平仓）
    if crash_protection_triggered(df):
        return True, 'crash_protection'
    # 优先级 2：因子反转
    if factor_reversal_triggered(df):
        return True, 'factor_reversal'
    return False, None
```

**优势**：
- 暴跌保护**真正独立判断**，不被因子反转覆盖
- 阈值差异能被测出（MA60 vs MA120 真的会不同）
- 风控触发时**有清晰日志**（crash_protection vs factor_reversal）

## 教训

### 教训 A：OR 复合信号有优先级陷阱

**错误假设**：
- "多信号 OR 复合 = 多重保险"
- 实际：高频信号会**完全覆盖**低频信号

**正确做法**：
- 高频信号（sell_ma5）和低频信号（暴跌保护）应**分层判断**
- 优先级：暴跌保护 > 因子反转（风控优先）

### 教训 B：风控应独立于入场逻辑（强化 L223 原则 1）

按 L223 原则 1（**风控与入场解耦**）+ L224：
- 解耦不只是"放在不同函数"
- 解耦是"**风控有独立触发逻辑，不被入场信号覆盖**"

**反例**：
```python
# 风控被入场逻辑掩盖
sell_signal = entry_factor_reversal | crash_protection
# entry_factor_reversal 每天触发，crash_protection 形同虚设
```

**正例**：
```python
# 风控独立判断，优先于入场逻辑
if crash_protection_triggered(df):  # 最高优先级
    sell(reason='crash')
elif factor_reversal_triggered(df):  # 次优先级
    sell(reason='factor')
```

### 教训 C：实验设计要避免变量混淆

**C19 设计缺陷**：
- 想测暴跌保护阈值差异
- 但 OR 复合让 sell_ma5 抢占了所有触发
- 5 个阈值结果一致 ≠ 阈值无差异，是**暴跌保护没起作用**

**正确实验设计**：
- 剥离 sell_ma5/sell_rsi/sell_obv
- 只测 crash 单一信号下的阈值差异
- 或者用独立风控逻辑重构后测阈值

### 教训 D：阈值没差异 ≠ 概念没价值

按规则 6.1（**诚实区分**）：
- 🔴 C19 实验显示 5 个阈值无差异
- 🟢 但**暴跌保护作为概念仍有价值**（要救回 -41% 暴跌）
- 🟢 问题是实现，不是概念

**结论**：
- 不应删除暴跌保护逻辑
- 应**重构**为独立判断（教训 B）
- 重构后再测阈值，才能找到最优值
